#### Added

- `lilypad-doctor` checks the `statement_timeout` of the role it connects as (with the database and server settings, and what the connection sets), and warns (`long-statement-timeout`) when there is none or it is longer than `maxStatementTimeout`. The gate sets no timeout by default, and a cache that stops waiting (`fetchTimeout`) does not stop its query: without a timeout, a query stuck on a lock or a dead connection holds its connection of the pool, and the writes of `LilypadDbCache` (`sqlCreate`, `sqlUpdate`, `sqlDelete`) wait with it. The warning has no fix SQL, since the doctor may run as another role than the application: its message gives the `ALTER ROLE ... SET statement_timeout` to run, and says where the current value comes from (the default, the server configuration, the database, the role, the connection).
- `maxStatementTimeout` option of `defineLilypadDb` (`@lilypad-studio/libs/schema`): the longest `statement_timeout` the doctor accepts, in ms (default: 1 minute), or `false` to skip the check. `checkLilypadSchema` takes it as an option too; run on the gate of the application, it also sees the gate's `statementTimeout`.
