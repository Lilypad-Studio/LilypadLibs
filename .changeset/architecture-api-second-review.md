#### Upgrading

| Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | What to do                                                                                                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`LilypadLogger.create` infers the channels from the keys of `components` only** (`@lilypad-studio/libs/logger`). A logger created without a type argument from component instances, such as `LilypadLogger.create({ components: { error: [new LilypadConsoleLogger()], info: [] } })`, was typed with the channels `string`: it could not be passed as the `logger` of a cache or a gate (TypeScript reported "has no properties in common"), and a call of a channel it does not have, such as `logger.warn(...)`, compiled and threw a `TypeError` at runtime. Such a call no longer compiles. The type uses `NoInfer`, which needs TypeScript 5.4 or later. | Call only the channels given in `components`, or add the missing ones to `components` (`warn: []` discards its messages). A variable typed `LilypadLoggerType<string>` takes `LilypadLoggerType<'error' \| 'info'>` (the channels of the logger) instead. |
| **A logger channel can no longer be named `dispose`** (`@lilypad-studio/libs/logger`): it is the new method `LilypadLogger.dispose()`, and `LilypadLogger.create` throws `Logger type "dispose" is reserved` for it, as for the other reserved names (`flush`, `register`...).                                                                                                                                                                                                                                                                                                                                                                                   | Rename the channel, e.g. `components: { dispose: [...] }` → `components: { disposal: [...] }`, and its calls.                                                                                                                                             |

#### Added

- `LilypadLogger.dispose()` (`@lilypad-studio/libs/logger`) waits for the messages logged so far, as `flush()` does, then removes a singleton logger from the registry, so that the next `LilypadLogger.create({ singleton })` with its identifier builds a new logger. `await using logger = LilypadLogger.create(...)` calls it at the end of the scope. The logger holds no resources: its channel methods keep working afterwards.
- The option types `LilypadLoggerOptions` (`@lilypad-studio/libs/logger`) and `LilypadSerializerOptions` (`@lilypad-studio/libs/serializer`), named like the options of the other classes (`LilypadCacheOptions`, `LilypadDbGateOptions`, ...).

#### Changed

- Deprecated: `LilypadLoggerConstructorOptions` and `LilypadSerializerConstructorOptions` are aliases of `LilypadLoggerOptions` and `LilypadSerializerOptions`, kept until 1.0. Replace `LilypadLoggerConstructorOptions<T>` with `LilypadLoggerOptions<T>`, and `LilypadSerializerConstructorOptions<FROM, TO, KeyMap>` with `LilypadSerializerOptions<FROM, TO, KeyMap>`.

#### Fixed

- The Quick Start of the README compiles: its logger can be passed to the gate and the cache (see Upgrading). The README gives the type of the `write` hook as it is, `LilypadDbPartialRow<T>` (a function typed `(data: Partial<T>) => Partial<T>` is rejected under `exactOptionalPropertyTypes`), and splits the config and the application of its first `LilypadDbCache` sample, which did not compile as one block.
