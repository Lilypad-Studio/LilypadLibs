#### Upgrading

| Change                                                                                                                                                                                                                                                                                                                                                                     | What to do                                                                                                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`LilypadFlowControl` checks the per-call `retries`** (`@lilypad-studio/libs/flow`). `executeFn({ retries })` and `executeWithRetries({ retries })` now reject before the first attempt when `retries` is not a non-negative integer. `NaN` used to retry for weeks, a negative value was treated as `0`, and `1.5` as 2 retries.                                         | Pass a non-negative integer, e.g. `retries: Math.max(0, Math.trunc(Number(process.env.RETRIES) \|\| 0))`.                                                                                                                             |
| **The default retry backoff of `LilypadFlowControl` is capped at 30 s** (`@lilypad-studio/libs/flow`). It was `2^attempt × 100` ms without a limit.                                                                                                                                                                                                                        | Nothing, unless you relied on longer waits: pass `backOffTime: (attempt) => 2 ** attempt * 100`.                                                                                                                                      |
| **Invalid numeric options throw a `RangeError`** instead of a plain `Error` (same messages). A `backOffTime` that returns an invalid delay now rejects with a `RangeError` whose `cause` is the error of the attempt.                                                                                                                                                      | Nothing, unless you compare `error.constructor === Error`: use `instanceof Error` or `instanceof RangeError`.                                                                                                                         |
| **The singleton keys of the `create()` methods carry a registry version**: `LilypadDbGate@1:<id>` instead of `LilypadDbGate:<id>` (same for `LilypadDbCache` and `LilypadLogger`). Two copies of the library in one process with a different registry version no longer share their singletons (each creates its own), so a copy never receives an instance it cannot use. | Close a singleton with its `close()`/`dispose()`, instead of `removeLilypadSingletonInstance('LilypadDbGate:<id>')` (`@lilypad-studio/libs/singleton`). If two versions of the library must share one gate, install a single version. |
| **`LilypadSerializer` refuses `__proto__` as a key** (`@lilypad-studio/libs/serializer`): the constructor throws `LilypadSerializer: "__proto__" cannot be a key.`. Such a key set the prototype of the output object, so its value was lost.                                                                                                                              | Rename the key.                                                                                                                                                                                                                       |

#### Added

- `LilypadRateLimitError.rateKey` (`@lilypad-studio/libs/flow`): the limited key (`<consumer>#<function>`, or the function alone), which was only in the message.

#### Fixed

- The `LilypadFlowControl` rate limit uses the monotonic clock (`performance.now()`). A step back of the system clock (an NTP correction, a resumed VM) used to refuse every recorded key until the clock caught up. `rate: 0` no longer records anything.
- The retries of the lazy `LISTEN`, of the changelog reads and of the gate heartbeat are no longer postponed by a step back of the system clock. They also keep retrying after more than 1024 consecutive failures.
- Background work (`platform.background`, `platform.afterResponse`) can no longer become an unhandled rejection, which terminates the Node.js process, when its error handler throws.
- A shared cache (`platform.shared`) never receives a `NaN` or `Infinity` TTL: a non-finite TTL becomes 1 second.
