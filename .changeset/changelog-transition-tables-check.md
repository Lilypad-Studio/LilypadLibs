#### Upgrading

| Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | What to do                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **The changelog SQL is now version 10 (`LILYPAD_CHANGELOG_VERSION`, `@lilypad-studio/libs/db`).** Its trigger function refuses to run for a trigger that does not declare its transition tables (see Fixed). `lilypad-doctor` (and `checkLilypadSchema`) reports an install of version 9 or older as the error `outdated-changelog`, and a statement trigger on the function without `REFERENCING OLD TABLE AS lilypad_old` / `NEW TABLE AS lilypad_new` now fails the writes of its table instead of running. | Run the changelog SQL again, in a migration, with the role that owns the changelog: the SQL that `lilypad-doctor --sql` prints for `outdated-changelog`, or `lilypadChangelogSql()` with your options. Services still on 0.8 keep reading the changelog (its rows are unchanged); their `lilypad-doctor` reports the new install as the warning `newer-changelog`, and withholds its changelog fixes, until they are upgraded. The triggers installed by `lilypadChangelogTriggerSql` need no change. |

#### Fixed

- The changelog trigger function (`lilypadChangelogSql`, `@lilypad-studio/libs/db`) can no longer be made to run another role's code as its owner. It reads the transition tables `lilypad_old` / `lilypad_new` by their unqualified names; for a statement trigger that does not declare them, PostgreSQL resolved those names in `pg_temp`, so a role granted `EXECUTE` on the function (which `CREATE TRIGGER` needs, e.g. the role of the migrations) could attach it, without `REFERENCING`, to a table of its own, and have it read a temporary view of its session: the functions of that view ran with the privileges of the changelog owner, a superuser when a superuser installed the changelog. The function now checks in `pg_trigger` that the firing trigger declares the transition tables of its event, and raises otherwise.
