#### Upgrading

| Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | What to do                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Large logged values are truncated** (`@lilypad-studio/libs/logger`). The text form of a logged value (`record.message`, the console and Discord lines) prints at most 100 items per array, set, map or object, followed by `… 900 more items` (`… N more properties` for an object). Both the text form and `toLogJson` (so `record.context` and the JSON lines) walk at most 10,000 objects per value; the others become `[…]`. A value whose levels share their children used to double the work at each level, and could block the logging call for hours; a list of 200,000 rows built a 7 MB string synchronously. | Nothing, unless you read full collections back from your logs: log them as a string part, which is written as it is, e.g. `logger.info('rows', JSON.stringify(rows))`. |

#### Fixed

- An `errorLogging` callback that logs on its own `LilypadLogger` (`@lilypad-studio/libs/logger`) no longer loops forever when a component keeps failing. The loop ran in microtasks only, so it hung the process. The failures of the messages that `errorLogging` logs synchronously now go to `console.error` only. Do not log on the same logger after an `await` inside `errorLogging`.
- A logged value that cannot be read (a `toJSON` or an iterator that throws, a Proxy trap) no longer replaces the whole message part or the whole context with `[Unformattable value]`: only that value does. `record.context` is always an object: a context that does not serialize to one is kept under `context` (`LilypadJsonConsoleLogger` used to write its characters as fields `"0"`, `"1"`...).
- The logger prints the `errors` of an `AggregateError`, e.g. each address that a failed connection to `localhost` tried. They were missing, and the error message is often empty.
- In the text form of logged values, nested strings and quoted keys escape their backslashes, line breaks and control characters as JSON does (`'C:\\Users'`), so a logged value can no longer start a new line of the output.
- `lilypadPinoLogger` follows the level changes of the pino logger it wraps (`logger.level = 'debug'`). It used to keep the level pino had when it was wrapped.
- `LilypadDiscordLogger` measures its throttling on the monotonic clock (`performance.now()`): a step back of the system clock no longer holds the messages, and `logger.flush()`, until the clock catches up. When the retries of a rate limited request run out, the next batch waits for the `retry-after` time given by Discord; beyond 30 seconds, the next batches fail without a request until that time. Truncated messages no longer end with half an emoji. The error of a failed batch no longer counts the "messages dropped" notice as a lost message.
- `LilypadLogger.register` with an inherited name (`constructor`, `toString`) throws `Logger type "..." was not defined...` instead of a `TypeError`.
