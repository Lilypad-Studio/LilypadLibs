#### Upgrading

| Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | What to do                                                                                                                                                                                                             |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`LilypadDbGate.create` checks the `pool` options and `statementTimeout`** (`@lilypad-studio/libs/db`). `pool.max` must be a positive integer, `pool.idleTimeout`, `pool.connectTimeout` and `pool.maxLifetime` a number of milliseconds from 0 (never) to 2147483647, and `statementTimeout` a positive number of milliseconds up to 2147483647; other values reject. They used to reach postgres.js as they were: `max: 0` made every query wait forever, a negative timeout fired at once, a `statementTimeout` above that bound made every connection fail, and `NaN` (for example `Number(process.env.X)` with the variable unset) silently meant never. | Pass valid values, or leave the option out to keep the postgres.js default (`idleTimeout: 0` still means never).                                                                                                       |
| **The changelog SQL helpers refuse a retention below one hour, as `pruneLilypadChangelog` does** (`lilypadChangelogSql({ prune: { olderThan } })` and `lilypadChangelogPruneScheduleSql({ olderThan })` in `@lilypad-studio/libs/db`). `olderThan` is in milliseconds: a retention given in seconds by mistake (`86_400` for a day is 86 s) made the trigger, or the pg_cron job, delete rows that the caches still had to read. The fix SQL of `lilypad-doctor` keeps an installed retention as it is.                                                                                                                                                        | For a retention below one hour on purpose, pass `force: true`: `lilypadChangelogSql({ prune: { olderThan: 30 * 60_000, force: true } })`, `lilypadChangelogPruneScheduleSql({ olderThan: 30 * 60_000, force: true })`. |

#### Fixed

- The changelog SQL (version 8: run `lilypadChangelogSql` and `lilypadChangelogTriggerSql` again, see its Upgrading row) works whatever the name of the changelog table and of its schema. A name that contained one of the placeholders of its SQL (`__lilypad_changelog__`, `__lilypad_prune__`...) installed a trigger function that failed every write to the cached tables. A name of 62 characters or more (schema included) made PostgreSQL truncate two of its functions, and two of its indexes, into one name: without `prune`, the SQL dropped its own trigger function (and failed on a reinstall); with `prune`, it failed; and the index on `changed_at` was never created. Those names are now cut with a hash, and the SQL drops the index that the earlier versions created under the truncated name; shorter names, and the default name of the pg_cron job of `lilypadChangelogPruneScheduleSql`, do not change.
- `lilypadChangelogSql` and `LilypadDbGate.addListener` reject an empty channel, or one longer than 63 bytes. `pg_notify` rejects such a channel, so the trigger failed every write to the cached tables; `LISTEN` truncates it, so its notifications were never delivered.
- `LilypadDbTable.selectByPrimaryKeys` returns the row of a key given several times once. A key that fell in two of its batches of 1000 keys returned its row twice.
